# 전세 온도계 글쓰기 지침 (예약 작업이 실행할 때마다 이 순서대로)

블로그: https://jeonse-ondogye.blogspot.com/ · 하루 1편 · 말투는 **합니다체** (청약노트의 해요체와 다르게)

## 0. 먼저 읽을 것
1. 저장소 루트의 `rules/adsense_approval.md` 2장(가치 있는 글의 조건)과 `rules/writing_rules.md`의 말투 규칙(24개 금지 규칙). 단, 이 블로그는 합니다체를 기본으로 한다.
2. `rules/blog_portfolio.md`: 전세 온도계는 전세가율·전세 흐름·보증금 위험 신호만 다룬다. 매매 시세만 다루는 글, 분양 이야기는 쓰지 않는다.
3. `blogs/jeonse/data/published.json`(쓴 글 기록), `blogs/jeonse/data/ranking.json`, `blogs/jeonse/data/regions/*.json`.

## 1. 글감 고르기 (먼저 해당하는 것 하나)

> **가치 분석 먼저(매번 필수, 애드센스 거절 사유 1위 대비)**: 글감을 고르기 전에 `python src/value.py --blog jeonse --brief`를 실행하고 `blogs/jeonse/data/value_brief.md`를 읽는다.
> - 글감은 그 파일 1번 표에서 '쓸 만함'(이 대상만의 두드러진 점 2개 이상)인 것 가운데 아래 규칙에 맞는 것으로 고른다. 아래 규칙이 고른 글감이 '쓰지 않음'이면 다음 후보로 넘어간다.
> - 고른 글감의 '두드러진 점'을 글의 중심(angle)과 소제목으로 삼는다. 숫자 나열이 아니라 그 숫자가 무슨 뜻인지 해설한다.
> - 2번 '오늘 피할 것'의 소제목·표현·시작 방식은 쓰지 않는다(검수가 여러 글에 반복된 표현을 막는다).

1. 월요일이고 ranking.json에 순위 지역이 15곳 이상이면 → **전세가율 순위 글**(type: ranking). 직전 순위 글과 다른 중심(상위, 변화, 수도권, 지방)으로.
2. 그 외 → **지역 전세가율 글**(type: region). regions/에서 아래 조건을 모두 만족하는 지역 중 jeonse_n84가 가장 많은 곳:
   - empty가 아니고 ratio84가 있으며 jeonse_n84 ≥ 20, sale_n84 ≥ 20
   - published.json에 같은 lawd 글이 없음(같은 지역은 다시 쓰지 않는다. 계산일이 60일 넘게 바뀐 뒤에만 "다시 보기" 글 허용)
3. 쓸 지역이 없으면 쓰지 않고 이유만 남긴다.

> **애드센스 점검(매번 필수)**: 글감을 고른 직후 `rules/precheck.md`의 A(1~5)를 하나씩 확인한다. 하나라도 걸리면 다른 글감으로 바꾸거나 쓰지 않고 이유만 남긴다. 통과하면 이 글이 더하는 가치를 한 문장으로 머리말 `value:`에 적는다.

## 2. 글의 중심(angle) 고르기: 그 지역에서 가장 두드러진 점 하나
| angle | 고르는 경우 |
| --- | --- |
| 전세가율 | 전국 순위가 상위·하위 20% 안이거나 ratio84가 70% 이상·45% 이하 |
| 흐름 | jeonse_change_pct 절댓값이 3 이상 |
| 동네차이 | umd에서 전세가율이 가장 높은 동과 낮은 동의 차이가 15%p 이상 |
| 단지분포 | apts_ratio_80_plus 또는 apts_ratio_70_plus가 눈에 띄게 많음 |
| 월세비중 | wolse_share_pct가 50% 안팎으로 높거나 아주 낮음 |
같은 종류 직전 2편과 같은 중심을 세 번 연속 쓰지 않는다(검수가 막음). 중심에 따라 소제목 수(3~5개), 표 위치, 선택 요소를 바꾼다.

## 3. 쓰는 법
- 첫 문장은 그 지역의 가장 구체적인 숫자로 시작한다(질문으로 시작하지 않는다).
- **계산 숫자 3개 이상**: 전세가율, 전국 순위, 최근 3개월 변화율, 동별 차이, 단지 수 등. 모든 숫자는 regions/<lawd>.json 또는 ranking.json에 있는 값만 쓴다. 직접 새 숫자를 계산해 쓰지 않는다(검수가 막음).
- **해설 문단 1개 이상**: 숫자가 세입자에게 무슨 뜻인지 조건을 나눠 쓴다. 예: "전세가율이 80%를 넘는 단지는 집값이 조금만 내려도 보증금을 돌려받기 어려워질 수 있습니다. 이런 단지에 들어간다면 전세보증보험 가입이 되는지부터 확인하는 편이 안전합니다."
- 단지 이름은 top_ratio_apts에 있는 것만, "전세가율이 높게 나온 단지"로 사실만 적는다. "위험한 단지", "깡통전세" 같은 판정은 쓰지 않는다.
- 표 2개 이상(4열 이하). 예: 동별 전세가율 표, 월별 전세 중앙값 표, 전세가율 높은 단지 표.
- 금액은 "4억 2,000만 원"처럼 쓴다. regions 파일의 금액 단위는 만 원이다.
- 끝부분: 개별 계약 전 확인할 것(등기부등본 근저당, 보증보험) 1~2문장 + 원자료 링크 [국토교통부 실거래가 공개시스템](https://rt.molit.go.kr) + 출처 문구.
- 출처 문구(뜻이 같으면 표현을 바꿔도 됨): "이 글의 숫자는 국토교통부 아파트 전월세·매매 실거래가 공개 자료로 직접 계산했습니다."
- 본문 1,500자 이상, 문단 4문장 이하, 굵은 글씨 2곳 이하, "~이 아니라" 1번 이하, 같은 어미 3문장 연속 금지.

## 4. 머리말

> **전세 키워드(2026-10-14 실제 검색량 확인)**: '○○구 전세가율'은 모든 구가 월 10회 미만이다. 사람들은 '○○구 아파트 전세', '○○동 아파트 전세'로 찾는다. 그래서 keyword와 제목 앞부분은 '○○구 아파트 전세'로 쓰고, 전세가율 숫자는 제목 뒤쪽과 본문에 둔다. data/keywords/jeonse.json에 검색이 있는 동(예: 자양동 660, 장안동 280)은 소제목에 동 이름을 넣어 그 동의 84㎡ 전세 중앙값·전세가율을 다룬다.

> **키워드 사다리(매번 필수)**: 머리말 keyword는 `rules/keyword_ladder.md`를 따른다. `data/keywords/jeonse.json`에 오늘 대상과 맞는 키워드(score 60 이상, used false)가 있으면 그것을, 없으면 '대상 이름 + 주제어'로 정한다. 머리 키워드(예: '전세가율', '깡통전세')는 쓰지 않는다(검수가 막음).

```
---
type: region            # 또는 ranking
lawd: "11680"           # 지역 글: 시군구 코드
title: "강남구 전세가율 52.3%, 84㎡ 전세 중앙값 ○억"   # 키워드를 앞 25자 안에, 60자 이하
slug: "gangnam-gu-jeonse-ratio-2026-10"
description: "50~160자 요약"
labels: [지역 전세가율, 서울]   # 2~3개: 지역 전세가율|전세가율 순위 + 서울|경기|인천|지방
keyword: "강남구 아파트 전세"   # 실제 검색은 '○○구 아파트 전세'(구·동). '전세가율'은 월 10회 미만이라 제목 뒤쪽에만
opening: A              # A 전세가율 숫자 / B 전세 보증금 / C 변화율 / D 동네 비교 (직전 글과 다르게)
angle: 전세가율
---
```

> **애드센스 점검(매번 필수)**: 검수(check)를 통과한 뒤 올리기 전에 `rules/precheck.md`의 B(6~12)를 하나씩 확인하고, 걸리는 것은 고친 뒤 검수를 다시 돌린다. 커밋 메시지 끝에 `점검: A1~5, B6~12 확인`과 value 문장을 적는다.

## 검색 노출 점검 (구글 SEO·AEO·GEO, 근거 rules/seo_guide.md, 2026-10-15 추가)
쓰는 동안 지키고, 검수가 확인한다.
- 지키지 않으면 발행 안 됨(검수 '[검색]' 오류):
  - 첫 문단에 검색 대상 이름과 핵심 숫자 또는 날짜를 넣어 답부터 쓴다.
  - 소제목(##)은 3개 이상 둔다.
  - 본문 문장 안에 출처를 밝힌다('청약홈 공고에 따르면', '국토교통부 실거래가 기준', 'K-apt에 공개된', 'DART 증권신고서에서').
  - 언제 자료인지 기준일을 쓴다.
  - '여기·더 보기' 같은 링크 문구는 쓰지 않는다.
- 되도록 모두 맞추기(검수가 '검색 권장'으로 보여 줌):
  - 제목은 40자 안팎으로 한다.
  - 질문형 소제목을 1개 이상 둔다. 사람들이 실제로 묻는 말로 쓴다.
  - 소제목 하나 이상에 대상 이름을 넣는다.
  - 소제목 바로 아래 첫 문장은 숫자 답으로 쓴다.
  - 110자 넘는 문장은 나눈다.
  - 문단을 '이는·그래서·또한'으로 시작하지 않는다. 문단만 떼어 읽어도 뜻이 통하게 쓴다(AI 답변은 문단을 잘라 인용한다).
  - 메인 키워드는 6번 이하로 쓴다.
  - 숫자 비교는 표로 쓴다.
  - 출처 문장은 2개 이상 둔다.
  - 용어는 처음 나올 때 한 번 풀이한다.
- 하지 않는 것: FAQ 구조화 데이터, 본문 속 스크립트, 키워드 나열.
- 검색 권장 항목은 글의 말투와 가치를 해치지 않는 범위에서 맞춘다. 데이터에 없는 숫자를 만들어 맞추지 않는다.

## 5. 검수와 올리기
1. 파일을 `blogs/jeonse/posts/pending/<오늘날짜>-<lawd>-<type>.md`로 저장한다.
2. `python blogs/jeonse/check_cli.py <파일>` 통과까지 고친다(최대 5번). 통과 못 하면 파일을 `blogs/jeonse/posts/held/`로 옮기고 사유를 남긴다.
3. 통과하면 commit·push. GitHub Actions(jeonse-publish)가 발행한다.
4. 규칙 파일, 코드, 데이터 파일은 고치지 않는다. 한 번 실행에 1편만.
