# 별도 검토자: 발행 전 품질 평가 (2026-10-18)

글을 쓴 쪽이 자기 글을 채점하면 기준이 느슨해진다. 그래서 검수(check)를 통과한 원고를 **글쓴이와 분리된 검토자**가 한 번 더 본다.
검토자는 구글 검색 품질 평가자처럼 읽는다. 질문은 하나다:
**"이 키워드로 찾아온 사람이 원자료 사이트(청약홈·국토부 실거래가·DART·K-apt)만 보면 되는가, 아니면 이 글을 읽을 이유가 있는가?"**

## 1. 실행 방법 (글쓰기 예약 작업)
1. 원고가 검수(check.py / check_cli.py)를 통과하면, commit 전에 Agent 도구로 새 에이전트(general-purpose)를 띄운다.
2. 에이전트에게 넘기는 것: 이 파일(rules/reviewer.md)의 2·3장 전문, 원고 파일 경로, 그 글의 데이터 파일 경로(대상 데이터 json), 최근 같은 블로그 공개 글 3편 경로.
   글쓴이의 생각이나 의도 설명은 넘기지 않는다(검토자가 원고만 보고 판단하게).
3. 판정이 '통과'면 '고칠 점'을 반영(숫자 규칙 지키며)하고, 검수를 다시 통과시킨 뒤 올린다.
4. 판정이 '보류'면 이유대로 한 번 고치고 검수 통과 후 다시 검토받는다. 두 번째도 '보류'면 posts/held/로 옮기고 사유 파일에 검토자 이유를 남긴다(그날은 억지로 올리지 않는다).
5. Agent 도구를 쓸 수 없는 환경이면 2·3장 기준으로 직접 검토하고, 끝 보고에 "별도 검토자 없이 자체 검토"라고 적는다.

## 2. 검토자 기준 (에이전트에게 그대로 전달)
너는 이 글을 쓰지 않은 검토자다. 구글 검색 품질 평가자처럼 엄격하게 읽는다. 원고와 데이터 파일만 근거로 판단한다.
- A. 고유한 가치(가장 중요): 원자료 한 곳만 열어서는 알 수 없는 것(여러 대상 비교, 순위, 중앙값·평균 대비, 기간 변화, 결과 추적, 숫자의 뜻 풀이)이 **2가지 이상**이고, 그것이 글의 중심인가?
- B. 첫 화면: 첫 두 문단 안에 그 고유한 점이 드러나는가? 공고·공시 내용을 옮기는 문장으로만 시작하지 않는가?
- C. 채움말: 대상 이름만 바꾸면 다른 글에도 그대로 쓸 수 있는 문단이 전체의 4분의 1을 넘는가?
- D. 해설: 표나 숫자 나열 뒤에 '그래서 무슨 뜻인지'를 풀어 주는 문장이 있는가?
- E. 정확성·정책: 데이터 파일과 숫자가 맞는가, 비율을 말로 부풀리지 않았는가(1.7배를 '두 배'), 투자·청약 권유나 단정('추천', '무조건', '안전')이 없는가?
- F. 반복: 최근 공개 글 3편과 소제목 뼈대·시작 문장·결론 문장이 같은 틀인가?

판정 규칙: A 또는 B가 미흡하면 '보류'. E에 틀린 숫자나 권유가 있으면 '보류'. C·D·F는 '통과'로 두되 고칠 점에 적는다.

## 3. 검토자 출력 형식 (이것만 돌려준다)
```
판정: 통과 | 보류
이유: (최대 3줄, 원고의 해당 문장을 짧게 인용)
고칠 점: (최대 3개, 각 한 줄. 데이터 파일에 있는 숫자로만 고칠 수 있는 제안)
```
