# 고유한 가치 장치: '공식 자료 정리 글'에서 벗어나기 (2026-10-18)

문제: 공공데이터를 옮겨 정리한 글은 다른 곳에서도 얻을 수 있어 구글이 '고유한 가치'로 인정하기 어렵다(애드센스 거절 1위 '가치가 별로 없는 콘텐츠').
해결 원칙: 원자료 사이트 한 곳을 열어서는 알 수 없는 것을 글의 중심에 둔다. 아래 장치가 그것을 자동으로 만든다.

## 1. 우리만의 시간 기록 (src/history.py, 매일 09:40)
- 4개 블로그 핵심 지표를 날짜별로 쌓는다: 전세(시군구·동 전세가율·전세/매매 중앙값), 관리비(시군구 중앙값·단지별 ㎡당 관리비), 공모주(시장 중앙값), 청약(지역 평당가).
- 4주·12주 변화를 미리 계산해 data/history/<블로그>_changes.json에 둔다. 글은 이 값을 그대로 쓰고(직접 계산 금지), 검수가 허용한다.
- 기록 시작 2026-10-18. 4주 변화는 2026-11-15쯤, 12주 변화는 2027-01-10쯤부터 생긴다. 시간이 갈수록 다른 곳에 없는 데이터가 된다.

## 2. 청약 공고 글 비교 의무 + 결과 이어 붙이기
- 공고(notice) 글은 같은 지역 최근 분양 단지와의 평당가 비교(N곳 중 M위, 평균보다 X%)가 없으면 발행되지 않는다(check.py notice_compare_errors).
- 1순위 경쟁률·당첨 가점이 발표되면 fetch 워크플로가 공고 글 끝에 결과 표와 결과 해설 글 링크를 자동으로 붙인다(publish.py --results). 한 단지의 공고→결과를 한 글에서 볼 수 있다.

## 3. 순위표 허브 페이지 (src/rankings.py, 매주 월 06:47)
- 블로그마다 고정 페이지 '순위표'(slug ranking)를 데이터로 만들고 모든 글 끝에서 링크한다.
  - 청약: 지역별 3.3㎡당 평균 분양가
  - 전세: 시군구 전세가율
  - 공모주: 공모 규모
  - 관리비: 시군구 ㎡당 관리비
- 시간 기록이 쌓이면 '4주 전 대비' 칸이 자동으로 생긴다.

## 4. 별도 검토자 (rules/reviewer.md)
- 검수를 통과한 원고를 글쓴이와 분리된 에이전트가 "원자료만 보면 되는가, 이 글을 읽을 이유가 있는가"로 판정한다. 두 번 보류면 올리지 않는다.

## 5. 청약 가점 계산기 (pages/calculator.md, 매주 갱신)
- 가점 계산(주택공급에 관한 규칙 별표 1 기준)과 함께, 최근 공고 단지의 실제 해당지역 당첨 최저 가점과 바로 견줘 준다. 청약노트 모든 글 끝에서 링크.

## 7. 우리 데이터로 그린 차트 (tools/chart.py, 2026-11-07)
- 사진·표 옮기기 대신 이 블로그 데이터로 직접 그린 그림. 글쓴이는 종류와 대상만 고르고, 값은 도구가 데이터 파일에서 읽는다(숫자 옮겨 적기 없음).
- captures/queue.json에 "chart" 항목 → capture 워크플로가 captures/<name>.webp로 저장(로그 captures/log.json).
- 종류: jeonse_dong, jeonse_sido, gwanribi_complex, gwanribi_sido, cheongyak_region, gongmoju_size, history(우리 매일 기록 선 그래프).

## 8. 블로그별 계산기 페이지 (src/calculators.py, 매주 월 rankings 워크플로)
- 청약 가점(5장) 외에 전세가율 계산기, ㎡당 관리비 계산기, 공모주 청약 증거금 계산기, 드론 신고·승인·보험 확인 계산기. 비교 기준값은 데이터 파일 값 그대로.
- 모든 글 끝에 블로그별 계산기 링크(publish.py CALC_TEXT).
- 글쓴이는 계산기에 조건을 바꿔 넣고 capture로 결과를 찍어 "제가 넣어 봤어요"를 쓴다. 캡처가 입력 행동을 증명한다(capture_guide 6-1·8장).
- 드론 계산기는 출처 노트로 확인한 조문만 쓴다(기체신고 2kg·사업용, 비행승인 25kg·관제권·비행금지구역·150m, 보험 사업용·공공용). 조종자 증명 종별 무게 기준은 1차 출처로 확인하지 못해 넣지 않았다(2026-11-07).

## 9. 결과로 맞춰 보는 후속 글 (src/followup.py, 매일 sitecheck)
- 이미 올린 글의 대상이 그 뒤 어떻게 됐는지: 전세·관리비·공모주는 글 올린 날 값(data/history) → 지금 값, 21일 이상 지나고 값이 바뀐 것만. 청약은 지난달 공고 단지들의 공고 때 3.3㎡당 분양가 → 실제 1순위 해당지역 경쟁률·최저 가점(결과 5곳 이상).
- data/followup/<blog>.json 후보, 원고 머리말 followup: <id>로 쓰면 다음 날 후보에서 빠진다. 검수 허용 숫자에 후보 값이 들어간다(check.py history_numbers).
- 시간이 갈수록 후보가 늘어난다. 공모주는 회사별 기록을 2026-11-07부터 쌓아 공모가 확정·정정 뒤 후보가 생긴다.

## 6. 아직 못 한 것
- 서치콘솔 성적 연결: 사용자가 구글 계정 권한(Search Console 읽기)을 한 번 승인해야 한다. 승인 전에는 노출·클릭 기반 보강을 할 수 없다.
- 순위표·계산기 페이지를 상단 메뉴에 넣는 것: Blogger 레이아웃 화면에서 사람이 '페이지' 가젯에 추가해야 한다(API로 안 됨). 글 끝 링크로는 이미 연결된다.
