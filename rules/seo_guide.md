# SEO·AEO·GEO 규칙 (글 쓸 때마다 먼저 읽기)

이 파일은 구글 공식 문서와 공개 연구를 2026년 10월 5일에 정리한 것이다.
구글은 순위 계산 방식을 공개하지 않는다. 아래는 "구글이 공식적으로 권하는 것"과
"연구로 확인된 것"만 담았고, 근거 수준을 [공식], [연구], [관행]으로 표시했다.

## 0. 가장 중요한 원칙
- [공식] 검색 순위가 아니라 사람에게 도움이 되는 글을 쓴다. 구글은 "사람 중심의
  도움이 되는 신뢰할 수 있는 콘텐츠"를 기준으로 삼는다.
- [공식] 청약은 돈과 관련된 주제라 신뢰(E-E-A-T)와 맞는 글을 더 무겁게 본다.
  (E-E-A-T 자체가 순위 요소는 아니라고 구글이 밝혔다.) 숫자를 틀리면 안 되고,
  출처를 문장 안에서 밝힌다.
- [공식] AI 사용 자체는 문제가 아니다. 순위 조작이 목적인 대량 생성이 문제다.
  자동화 사용 사실을 글 하단에 밝힌다.
- [공식] AI 개요·AI 모드에 나오기 위한 별도 최적화는 없다. 일반 SEO 기본이 그대로 적용된다.
  llms.txt 같은 AI 전용 파일은 만들지 않는다.

## 1. 하면 안 되는 것 (스팸 정책) [공식]
- 대량 생성 콘텐츠 악용: 사람에게 도움이 아니라 순위 조작이 주목적인 다량의 페이지.
  → 새 정보가 없는 날 글을 짜내지 않는다. 같은 단지·같은 유형 글을 두 번 쓰지 않는다.
- 스크래핑: 다른 사이트 글을 거의 그대로 옮기기. → 공고 데이터를 표로 옮기는 데서
  그치지 않고, 비교·계산·정리로 가치를 더한다.
- 키워드 반복: 같은 키워드, 지역명 나열, 숫자 덩어리. → 메인 키워드는 제목·첫 문단·
  소제목 1~2곳에 자연스럽게만.
- 도어웨이: 거의 같은 페이지를 지역만 바꿔 여러 개 만들기. → 지역 모음 글은 지역마다
  실제로 다른 단지·숫자가 있을 때만 쓴다.

## 2. 제목 (title) [공식]
- 짧고 설명적으로. 길면 기기 폭에 맞춰 잘린다. 목표 40자 안팎.
- 글마다 다른 제목. 같은 틀만 반복하지 않는다.
- 단지명 + 검색어(청약 일정, 분양가, 경쟁률 등)를 앞쪽에 둔다.
- 키워드를 여러 번 넣지 않는다.
- 본문 첫 제목(h1 역할)은 글 제목과 같은 뜻으로, 화면에서 가장 크게 보이게 한다.

## 3. 검색 설명 (meta description) [공식]
- 글마다 다르게, 그 글에만 있는 정보로 쓴다.
- 날짜·가격 같은 흩어진 핵심 정보를 한데 모아 쓰면 좋다.
  예: "1순위 10월 14일, 84㎡ 최고가 6억 2천만 원, 총 812세대."
- 키워드 나열 금지. 사람이 읽는 문장 1~2개, 120자 안팎.
- 구글은 대부분 본문에서 스니펫을 만들기 때문에, 본문 첫 화면에 답을 둔다.

## 4. 본문 구조 (AEO: 답을 먼저) [공식 + 관행]
- [공식] 검색어에 쓰일 말을 제목, 주요 소제목, 이미지 대체 텍스트, 링크 문구에 쓴다.
- [관행] 질문형 소제목 바로 아래 1~2문장으로 답부터 쓰고, 설명은 그다음에.
- [공식] 접는 영역 안에 핵심을 숨기지 않는다. 바로 보이는 내용이어야 '더 보기'
  딥링크 대상이 된다.
- [공식] FAQ 리치 결과는 2026년 5월부터 검색에 나오지 않는다. '자주 묻는 질문'은
  독자를 위해서만 넣고, FAQ 구조화 데이터는 쓰지 않는다.

## 5. GEO: AI 답변에 인용되게 [연구]
- 2024년 KDD 학회 GEO 논문: 통계 추가, 인용(출처 문장) 추가가 AI 답변 노출을
  30~40% 늘렸고, 읽기 쉬운 문체가 15~30% 늘렸다. 키워드 반복은 효과가 없거나 나빴다.
- 그래서: 주장마다 숫자, "청약홈 입주자모집공고에 따르면"처럼 출처 문장,
  짧고 쉬운 문장, 용어는 처음 나올 때 한 번 풀이.
- 단독으로 읽어도 뜻이 통하는 문장으로 쓴다(앞 문장을 안 봐도 이해되게).
  AI 답변은 문단 단위로 잘라 인용하기 때문이다. [관행]

## 6. 링크 [공식]
- 링크 문구는 설명적으로, 짧게. "여기", "더 보기" 금지.
  좋은 예: "OO단지 1순위 경쟁률 결과", "청약 가점 계산법".
- 링크를 연달아 붙이지 말고 문장 속에 자연스럽게.
- 중요한 글은 사이트의 다른 글 최소 1곳에서 링크를 받아야 한다.
  → 단지 글끼리, 단지 글 ↔ 월간 정리(허브) 글을 서로 잇는다.
- 외부 링크는 신뢰할 출처(청약홈 공고 원문 등)로.

## 7. 이미지 [공식]
- 이미지를 넣을 땐 <img> 태그 + 설명적인 대체 텍스트(alt). alt에 키워드 나열 금지.
- 관련 문단 가까이에 둔다. 용량을 줄여 로딩을 빠르게.
- 저작권이 있는 조감도·평면도 이미지를 그대로 가져오지 않는다. 직접 만든 표·그래프만 쓴다.

## 8. 페이지 경험 [공식]
- HTTPS, 모바일에서 잘 보이기, 본문을 가리는 광고·팝업 금지.
- 코어 웹 바이탈(LCP, INP, CLS)이 순위 시스템에 쓰인다. 다만 단일 신호는 아니고
  관련성이 더 중요하다. 가벼운 테마, 큰 이미지 지양.

## 9. 구조화 데이터 [공식]
- 블로그 글은 Article/BlogPosting으로 headline, image, datePublished, dateModified,
  author(name, url)를 표시할 수 있다. Blogger 테마가 기본 제공하는지 확인하고,
  부족하면 테마에서 보완한다(글 본문에 스크립트를 넣지 않는다).

## 10. 신뢰 장치 (E-E-A-T, Who·How·Why) [공식]
- Who: 블로그 소개 페이지에 운영자와 운영 방식을 밝힌다.
- How: 글 하단 고정 문구 "이 글은 청약홈 공고 데이터를 바탕으로 자동 정리했어요.
  신청 전에는 반드시 입주자모집공고 원문을 확인해 주세요."
- Why: 청약 신청자가 일정·가격을 빠르게 확인하도록 돕는 것이 목적임이 드러나게.
- 정정이 생기면(정정공고) 글을 고치고 수정일을 갱신한다.

## 11. Blogger 설정 체크리스트 (사람이 한 번)
- 설정 → HTTPS 리디렉션 켜기
- 설정 → 메타 태그 → 검색 설명 사용 켜기, 블로그 전체 설명 입력
- 설정 → 크롤러 및 색인 생성 → 맞춤 robots.txt는 기본값 유지(잘못 쓰면 색인이 막힘)
- 소개·개인정보처리방침·문의 페이지 만들기
- 서치콘솔에 사이트맵(/sitemap.xml) 제출
- 메뉴 이름은 Blogger가 바꿀 수 있어 실제 화면과 다를 수 있다.
