# 애드센스 거절 사유 상위 항목과 매일 점검 (2026-10-14 조사)

[사실] 구글은 거절 사유별 빈도 통계를 공개하지 않는다. 아래 순서는 국내·영어권 운영자 후기와 정리 글에서
얼마나 자주, 얼마나 크게 다뤄지는지를 기준으로 한 우리 판단이다. 상세 근거는 rules/adsense_approval.md.

| 순위 | 거절 사유 | 흔한 원인 | 우리 블로그의 위험 | 매일 확인하는 방법 |
| --- | --- | --- | --- | --- |
| 1 | 가치가 별로 없는 콘텐츠 | 짧은 글, 비슷한 틀 글 반복, 옮겨 적기, 자동 생성 후 검토 없음 | **가장 높음** (공공데이터 자동 글) | 새 글 점검(precheck), audit.py 반복 문장·약한 글, sitecheck 짧은 글 |
| 2 | 사이트 미완성·필수 페이지 없음 | 소개·문의·개인정보 페이지 없음, 빈 카테고리, 시험 글, 깨진 링크 | 높음 (새 블로그 3개 소개·문의 없음) | sitecheck: 필수 페이지, 시험 글, 깨진 내부 링크, 8편 미만 라벨 |
| 3 | 사유 없는 거절(정책 준수 문구만) | 애드센스 지급 프로필 주소 오류 | 신청 때 | 사용자: 지급 정보 주소를 도로명+동·호수로 정확히 |
| 4 | 탐색·사용 경험 | 메뉴 없음, 홈으로 못 돌아감, 모바일 불편, 3번 넘게 눌러야 글 도달 | 중간 | sitecheck: 홈의 라벨 메뉴·페이지 링크, viewport |
| 5 | 너무 새 사이트·색인 부족 | 개설 직후 신청, 같은 날 글 몰아 올림, noindex | 중간 (개설 1~2주) | sitecheck: noindex, 발행 멈춤 / 사용자: 서치콘솔 색인 수 |
| 6 | 정책 위반 | 저작권 침해, 오해 소지 있는 돈·건강 주장 | 낮음~중간 (돈 주제) | 검수 금지어(권유·단정), precheck B9·B10, 이미지 미사용 |
| 7 | 중복 콘텐츠 | 거의 같은 틀 글, 기계 번역, 출처 글 그대로 | 1번과 겹침 | audit.py 겹침·합치기 후보, 틀 문장 |

## 매일 하는 일
1. GitHub Actions `sitecheck`(매일 09:40 KST)가 4개 블로그 공개 화면을 확인해 data/sitecheck.md를 남긴다(무료, 코드만).
2. 예약 작업 "애드센스 거절 사유 매일 점검"(매일 10:37 KST)이 sitecheck.md와 audit.py 결과를 읽고 위 표 순서대로 판단한다.
   - 바로 고치는 것: 1·7번(최근 글의 틀 문장, 해설 부족, 틀린 숫자), 2번 중 깨진 내부 링크(원고 수정), 분석 방법 페이지 누락(pages 재게시).
   - 사용자에게 넘기는 것: 2번 소개·문의 페이지 내용(운영자 이름·이메일), 시험 글 삭제, 3번 지급 주소, 5번 서치콘솔 확인, 라벨 메뉴 가젯 설정.
   - 비공개·삭제·합치기는 하지 않고 data/audit_actions.md에 제안만 적는다.
3. 3일마다 하는 전체 재점검(rules/audit_routine.md)은 따로 그대로 한다(이전 글 전부 다시 읽기).
