# 애드센스 승인 규칙 (2026-10-12 정리, 모든 블로그 공통)

[공식] 구글 문서, [사례] 운영자 경험담(구글 확인 아님), [가정] 우리 판단.
승인은 누구도 보장할 수 없다. 이 파일은 거절 위험을 줄이는 규칙이다.

## 1. 기준이 되는 사실
- [공식] 애드센스 게시자 정책 '복제된 콘텐츠': 다른 곳 내용을 큐레이션·해설로 가치를 더하지 않고 싣는 것을 금지한다.
  예시에 "수동 검토나 큐레이션 없이 자동으로 생성된 콘텐츠", "동의어만 바꾼 가벼운 수정"이 있다.
  해법: 전문 지식, 개선 아이디어, 리뷰, 개인적 생각 같은 원본 콘텐츠와 해설을 더한다.
- [공식] 구글 '도움이 되는 콘텐츠': 단순 복사·재작성이 아닌 실질적 가치, 다른 검색 결과보다 나은 정보, 직접 경험을 묻는다.
  경고 신호: 다른 사람 작업을 가치 없이 요약하기, 검색 유입만 노리고 여러 주제로 페이지를 많이 만들기.
- [공식] 비슷한 페이지가 많으면 각 페이지를 보강하거나 하나로 합치라고 안내한다.
- [사례] 거절 사유 1위는 '가치가 별로 없는 콘텐츠'. 같은 스타일 글을 더 쌓아 재신청하면 같은 이유로 또 거절된 사례가 많다.
- [사례] 운영자 실명 없음, "AI가 만들고 사람이 손보지 않았다"는 문구, 빈약한 카테고리가 원인으로 꼽힌 사례가 있다.
- [사례] 사이트가 너무 새것이고 방문자가 없으면 거절된다는 보고가 있다.
- [사례] 사유 없는 거절은 애드센스 지급 프로필 주소 오류인 경우가 많다고 한다.
- 우리 사정: 사람의 검토와 직접 경험은 없다(사용자 결정). 그래서 '가치를 더했는가'를 최대한 강하게 만든다.

## 1-1. '가치가 별로 없는 콘텐츠' 심층 조사 (2026-10-12)
- [공식] 거절 문구의 근거는 게시자 정책 '게시자 콘텐츠가 없는 화면에 게재되는 Google 광고'(answer/11112688).
  금지: 콘텐츠가 없거나 가치가 낮은 화면, 공사 중 화면. 위반 예시에 "수동 검토나 큐레이션 없이 자동 생성된 콘텐츠".
  권장: "자동 생성 콘텐츠는 광고 전에 수동 검토·큐레이션", "페이지를 다 만든 뒤 광고". 판정 단위가 '화면'이라 약한 페이지 몇 개도 문제가 될 수 있다.
- [공식] 애드센스 블로그: 템플릿과 적은 내용뿐인 사이트는 거절될 수 있다. 재신청 전 "내 페이지를 고유하게 만드는 것"을 생각하라.
- [공식] 품질 평가 가이드(2025.1): 거의 전부 자동 생성이면서 노력·독창성·추가 가치가 거의 없으면 최저 등급(출처를 밝혀도).
  '채움말(Filler)'은 내용이 많아 보이게만 하는 문장이라 감점 요소.
- [공식] 유용한 콘텐츠 자가진단: 독창적 분석이 있는가, 다른 검색 결과보다 실질적 가치가 있는가, 누가·어떻게·왜 만들었는지 보이는가.
- [사례, 가장 구체적] 프로그래매틱 디렉터리 사이트가 4번 거절. 점검하니 같은 문장이 467번 반복(같은 틀 + 비슷한 입력 = 같은 문장).
- [사례 다수] 글 수는 결정 요인이 아니다(10편 승인, 50편 거절). 13편으로 줄이고 주제를 하나로 정리한 뒤 승인된 사례도 있다.
- [사례 다수] 제목·소제목·문장 패턴이 모든 글에서 같으면 의심받는다.
- [사례 소수] 블로그스팟: 보관함·검색 페이지 noindex, 홈에 실제 글이 보이게, 비어 있는 정적 페이지 정리.
- 우리 상황에서 남는 위험: '수동 검토 없음'은 정책 예시 문구에 그대로 해당한다. 아래 규칙은 '큐레이션과 가치 추가'를 최대한 보여 주는 방법이고, 위험을 0으로 만들지는 못한다.

### 이에 따른 자동 장치 (2026-10-12 적용)
- check.py: 다른 공개 글과 숫자만 다른 같은 문장(틀 문장) 2개 이상이면 발행 안 함. 채움말 금지어 추가.
- publish.py: 관련 글 묶음(같은 단지 → 같은 지역 → 같은 종류, 최대 6개)을 붙이고, 새 글이 오면 이전 글 묶음도 갱신.
- 분석 방법 페이지에 '글은 이렇게 만들어요'(숫자 대조, 분석 숫자 기준, 중복 금지, 얇은 공고 모음)를 공개 = 큐레이션 절차를 드러냄.

## 2. 글마다 지킬 것 (가치가 별로 없는 콘텐츠를 피하는 핵심)
1. 계산한 분석 숫자 2개 이상 (check.py가 확인). 원본을 옮기는 문장보다 계산·비교 문장이 많아야 한다.
2. **해설 문단 1개 이상**: 숫자가 뜻하는 것을 풀고, 조건을 나눠 판단을 돕는다.
   예: "84㎡ 일반공급을 노린다면 특공보다 물량이 적어 1순위 해당지역 안에서 승부가 날 가능성이 커요.
   반대로 신혼부부 특공 조건이 된다면 이 단지는 특공 물량이 125세대라 기회가 넓은 편이에요."
   (근거 숫자는 데이터에서. '무조건', '꼭 넣으세요' 같은 권유·단정 금지)
3. 다른 글로 바꿔 끼워도 되는 문장은 쓰지 않는다. 문장마다 그 단지·지역만의 숫자·날짜·지명.
4. 직전 10편과 구조가 달라야 한다 (시작 방식, 소제목, 선택 요소. check.py가 확인).
5. 같은 단지·지역·주제로 글을 두 번 쓰지 않는다. 새 데이터가 나오면 새 단계 글(경쟁률→가점)로 잇는다.
6. 원본 사이트(청약홈 등)를 옮겨 적는 표는 최소로. 표는 비교·순위·계산값 위주.
7. 끝에 출처 안내 문구: "이 글은 ○○ 데이터를 바탕으로 정리했어요." (데이터 출처를 앞세운다)
8. 모든 글 끝에 '분석 방법과 데이터 출처' 페이지 링크 (publish.py가 자동으로 붙인다).

## 4. 신청 시점
- [사례 기반 가정] 글 30~40편 이상, 카테고리마다 5편 이상, 블로그 개설 1~2개월 뒤, 서치콘솔에 검색 노출이 생긴 뒤.
- 블로그 여러 개는 한꺼번에 신청하지 않는다. 가장 강한 블로그부터 신청하고 결과를 다음 블로그에 반영한다.
- 신청 전 점검: 얇은 글(분석 숫자 적음, 짧음, 비슷함)은 보강하거나 합치거나 내린다(내리기 전 사용자와 상의).

## 5. 거절되면
1. 거절 사유를 기록한다 (data/adsense_log.md).
2. 같은 스타일 글을 더 쌓지 않는다. 가장 약한 글부터 보강·통합하고, 해설·계산값을 늘린다.
3. 2주 정도 두고 재신청한다. 같은 사유로 3번 거절되면 진단을 다시 한다.
