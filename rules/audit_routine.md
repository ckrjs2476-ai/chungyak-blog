# 3일마다 하는 애드센스 전체 점검 (4개 블로그, 이전 글 모두 포함)

근거: rules/adsense_approval.md, rules/precheck.md. 대상: 청약노트(cheongyak), 전세 온도계(jeonse), 공모주 뜯어보기(gongmoju), 관리비 돋보기(gwanribi).

## 1. 기계 점검
블로그마다 `BLOG_KEY=<key> python src/audit.py` → audit.md (청약노트 data/audit.md, 나머지 blogs/<key>/data/audit.md).
보는 것: 약한 글(점수 70 미만, 검수 오류), 겹침·합치기 후보, 2편 이상 반복 문장 비율(목표 5% 미만), 3편 이상 반복 문장, 라벨별 글 수(8편 미만).

## 2. 사람 눈 점검 (Claude가 글을 직접 읽고 판단)
블로그마다 지난 점검 뒤 새로 올라온 글 전부 + 점수 낮은 글 5편을 실제로 읽고 rules/precheck.md B(6~12)로 판단한다.
- 얕은 글: 숫자 나열뿐이고 해설이 없음 / 다른 글과 같은 이야기 / 원자료를 옮겨 적은 것뿐
- 바꿔 끼워도 되는 문단, 채움말, 판정·권유 표현
- 블로그 전체로 보아 같은 뼈대(시작 문장·소제목·표 배치)가 반복되는가

## 3. 바로 고치는 것 (자동, 공개 주소·제목·날짜는 그대로)
- 대상: 위에서 걸린 글. 한 번에 블로그당 최대 5편.
- 방법: `posts/published/<파일>`(청약노트) 또는 `blogs/<key>/posts/published/<파일>` 원고를 고친다.
  - 데이터에 없는 숫자 → 현재 데이터 값으로 바꾸거나 그 문장을 지운다. 지어내지 않는다.
  - 틀 문장·반복 문장 → 그 글만의 숫자·지명으로 다시 쓴다.
  - 해설이 없으면 → 데이터로 뒷받침되는 해설 문단을 더한다.
  - 같은 블로그의 관련 글로 본문 문맥 링크 1~2개를 더한다(공개 주소는 published.json의 url).
- 고친 원고는 그 블로그의 검수(`python src/check.py <파일>` 또는 `python blogs/<key>/check_cli.py <파일>`)를 통과해야 한다. '직전 글과 같은 opening/angle' 오류는 이미 올린 글이라 무시한다.
- 커밋·push하면 GitHub Actions(rerender-on-edit)가 공개 글을 다시 만든다.

## 4. 사용자 확인이 필요한 것 (제안만, 직접 하지 않음)
비공개, 삭제, 두 글 합치기, 라벨 없애기·합치기는 주소가 사라지거나 바뀌므로 직접 하지 않는다.
`data/audit_actions.md` 맨 위에 날짜와 함께 제안을 적는다: 무엇을, 왜(audit 숫자 근거), 어떻게(어느 글로 합칠지).

## 5. 기록과 보고
- audit.md 4개, 고친 원고, data/audit_actions.md를 커밋한다. 메시지: `애드센스 3일 점검 <날짜>`.
- 마지막에 블로그별로 한 줄씩: 공개 글 수, 고친 글 수, 남은 약한 글, 사용자 확인 필요한 제안 수.
- 규칙 파일, 코드(src/, blogs/*/*.py), 데이터 파일(data/, blogs/*/data/의 json)은 고치지 않는다.
